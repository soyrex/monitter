## Interface-scale implementation seam

Treat interface scale as visual zoom, separate from display/device scale. The locked local SDK is GPUI pre 0.3.7 (`desktop-gpui/Cargo.lock`). In `/Users/alex/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/gpui-pre-0.3.7/src/window.rs`, `Window::scale_factor()` (around line 2925) reports display backing scale; `set_rem_size()` (around line 2947) is explicitly the app UI/rem-size adjustment. Do not change `scale_factor` to implement the preference: that changes physical-pixel mapping and risks Retina rendering/input coordinates. GPUI Kit 0.7.0's `src/root.rs:436` sets rem size from the theme font size. This can scale rem-based styles and text, but app layout uses many hard-coded `px()` dimensions, so it cannot alone reproduce Tauri page zoom. No generic GPUI whole-tree zoom was found in the locked API.

Implementation path: keep OS window bounds and backing scale unchanged; derive `zoom = interfaceScale / 100`; set the root theme/rem font size from the interface base size times zoom, then migrate app-owned dimensions and font sizes from raw `px(value)` to one explicit `ui_px(value, zoom)` conversion. Keep native frame/titlebar coordinates OS-controlled, and audit GPUI Kit controls for their own literal pixel sizes. For embedded WKWebView content, `wry-0.55.1/src/wkwebview/mod.rs:933` exposes `WebView::zoom(f64)` and `desktop-gpui/vendor/gpui-wry/src/lib.rs:211` maps GPUI layout bounds to Wry logical bounds and a matching hitbox. Apply page zoom only when supported end-to-end, then verify resize, pointer/hit-test alignment and viewport behavior at 80%, 125%, and 200%. Do not claim global zoom until that migration and native verification pass.
