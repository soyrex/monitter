# GPUI desktop parity acceptance

This is a target checklist, not a report of completed or verified behavior. Check an item only after exercising it in a built native GPUI app against isolated test data. Source pointers name the original UI contract to compare. The visual cohort source-test log reports 14 library and 53 binary tests passed (0 failures; 0 doc tests). One native GPUI renderer-frame image is available, but it omits macOS traffic lights/titlebar and the WKWebView child; it is not full-window or interaction acceptance. Compact sidebar/toolbar changes followed the captured package and still need a later build and review. Keep every item unchecked until native UI exercise.

## Deferred visual enhancement requested by Alex

Priority clarification: ordinary native window blur is sufficient and is the target. Actual Liquid Glass is optional and lower priority; it must not delay the blur option or core parity.

- [ ] Investigate optional native macOS window transparency and background blur after core desktop parity. Distinguish actual Liquid Glass APIs from ordinary vibrancy/blur; use supported GPUI/AppKit integration rather than imitating glass with translucent rectangles. Keep text and controls legible, respect reduced-transparency accessibility preferences, provide an opaque fallback, and measure compositing cost. This is a later visual enhancement, not a current build claim.

Initial feasibility evidence: pinned `gpui-pre-0.3.7` exposes `WindowBackgroundAppearance::{Opaque,Transparent,Blurred}`; `gpui-pre-macos-0.3.7/src/window.rs` implements blur with `NSVisualEffectView`. This is ordinary native vibrancy, not proof of Liquid Glass. Apple's [NSGlassEffectView](https://developer.apple.com/documentation/appkit/nsglasseffectview) is the separate API to investigate for a true Liquid Glass treatment. No transparency implementation or runtime verification has been performed.
