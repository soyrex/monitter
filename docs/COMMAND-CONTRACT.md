# Command contract

`command-contract.json` is the checked inventory for Tauri commands. Each entry records the Rust command's argument names and types, result type, and explicit native/LAN surfaces. `scripts/command-contract.mjs` reads `#[tauri::command]` signatures and compares them with `generate_handler!`, the local Tauri permission list, and the explicit LAN dispatcher. LAN dispatch checks the manifest before matching a command, so adding a Rust command does not make it remotely available. Only `native` and `lan` are Tauri surfaces; controller and visitor actions are separate protocol mappings and are checked against their protocol/dispatcher code.

The script generates `src/lib/generated-command-contract.ts`; `src/lib/command-invoke.ts` and `src/lib/bridge.ts` use its argument and result maps so call sites cannot select an unregistered command or change its signature without updating the Rust contract. The client first requests `get_command_capabilities`. A missing handshake is treated as a legacy backend and permits only the existing legacy read/send paths. A present but unsupported protocol version fails closed. A fast send is selected only when both fast-send commands are advertised, and its failure is surfaced without retrying a potentially accepted mutation.

The controller section records each action's explicit native-command mapping and semantics. Multi-step attachment upload actions map to an in-memory controller operation, with only finish mapped to `store_attachment`. Visitor allowed actions likewise state the owner commands they compose; denied actions remain a separate list and cannot acquire mappings accidentally.

The generator treats Rust `History<T>` as the same serialized JSON array shape as `Vec<T>`. UI sync results use the nominal TypeScript types `UiDeltaResponse` and `TaskMessagesPage`; the delta carries only changed message records plus explicit retention IDs for unchanged channel and subagent histories.

The checker also compares Rust and TypeScript member names for `Host`, `Agent`, `Task`, `Message`, `Project`, `Channel`, `Settings`, `Snapshot`, `CreateTaskInput`, `HandoffTaskInput`, and `ForkTaskInput`. Other nominal types used by command arguments/results are listed explicitly in `memberParity.unsupported` in the JSON manifest. Their Rust command signatures are checked and generated TypeScript points to their named types, but their serialized member shapes are not yet mechanically compared; remove each name from that list only when a structural check covers it. `JsonValue` deliberately represents recursive `serde_json::Value` payloads.

After a deliberate Rust command/surface change, run `npm run contract:write`, review both generated files, then run `npm run contract:check` and `npm run check`. The `Command contract` workflow runs those checks plus a focused Rust test that verifies native/LAN capability scoping. Live-provider and UI smokes remain opt-in and are not prerequisites for this contract check.
